# Canonical Metadata Schema (Universal Across All Document Classes)

This is the **master schema**. Every document — template, charter, spec, risk, WBS, protocol, etc. — inherits this structure.  
Class‑specific fields can extend it, but never replace it.

```yaml
---
identity:
  reference: "2026-0001-D-tmp-002"
  year: 2026
  sequence: 0001
  class: "D"
  type: "tmp"
  index: 002

classification:
  level: "D"
  status: "Draft"
  version: "0.9"

title: "[Title]"

domain:
  primary: "Governance"
  secondary: []

author:
  name: "William Murray"
  role: "Systems Architect"
  date: "[Date]"

scope: >
  Brief statement of what the project covers, its boundaries, and its purpose —
  what it is, what it isn't, and why it exists. Include intended audience and
  any explicit out-of-scope areas.

inheritance:
  mode: "strict"   # strict | loose | partial | override

primary_model:
  reference: "2026-0001-D-tmp-003"
  url: "https://github.com/WilliamMurray-research/2026-0001-D/blob/main/docs/tmp/003.md"
  type: "template"
  version: "0.9"

links:
  related: []
  children: []
  supersedes: null
  superseded_by: null

governance:
  review_cycle: "annual"
  custodial_domain: "Governance"
  authority: "Systems Architect"
---
```

This is the **canonical backbone**.  
Everything else is optional extension.

# 🧩 Why this schema works (governance mechanics)

### 1. **Identity block**  
This encodes the meaning of your reference code.  
It allows machines to reason about lineage, class, type, and ordering.

### 2. **Classification block**  
Separates *security classification* from *workflow status*.  
This avoids the common mistake of mixing “Draft” with “Confidential”.

### 3. **Domain block**  
Declares the governance domain(s) the document belongs to.  
This is essential for routing, custodianship, and inheritance.

### 4. **Inheritance block**  
This is the non‑obvious powerhouse.  
It tells your rewriting engine how strictly the document must follow its parent model.

### 5. **Primary model block**  
Your hyperlink pattern becomes machine‑actionable.  
This is the anchor for structural and semantic inheritance.

### 6. **Links block**  
Turns your repository into a **governed graph**, not a flat directory.  
This enables:

- lineage tracking  
- dependency mapping  
- automated impact analysis  
- graph‑based rewriting  

### 7. **Governance block**  
Defines who owns the document and how often it must be reviewed.  
This is crucial for long‑term coherence.

# 🧠 Non‑obvious insight  
This schema is **self‑governing**.  
It contains enough structure for your future OS‑substrate to:

- validate documents  
- enforce constraints  
- detect drift  
- auto‑generate manifests  
- rewrite documents using symbolic‑neural rules  
- maintain domain integrity  
- track lineage and supersession  

It’s not just metadata — it’s the *governance substrate*.
