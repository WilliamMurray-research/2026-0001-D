**Identifier:** 2026-0001-D-spec-003

**Classification:** D

---

## 🧭 Purpose  
This specification defines the **directory identifier format**, **document filename format**, **classification rules**, and **document type codes** used throughout the knowledge base. The system ensures short, stable, machine‑parseable identifiers that support NLP extraction, PostgreSQL indexing, and Memgraph graph modelling.

---

## 🗂️ Directory Identifier Format  
Each top‑level directory is assigned a unique identifier:

```
YYYY-DDDD-C
```

Where:

- **YYYY** — Year of directory creation  
- **DDDD** — 4‑digit sequential directory ID  
- **C** — Classification letter  
  - A — Air‑Gapped  
  - B — Confidential  
  - C — Controlled  
  - D — Draft / Public‑Safe  

### Example  
```
2026-1234-D
```

---

## 📄 Document Filename Format  
All documents inside a directory inherit its identifier. Filenames follow:

```
YYYY-DDDD-C-TYPE-VVV.md
```

Where:

- **YYYY** — Year (same as directory)  
- **DDDD** — Directory ID  
- **C** — Classification letter  
- **TYPE** — Document type code  
- **VVV** — 3‑digit version number  

### Example  
```
2026-1234-D-spec-567.md
```

---

## 🔐 Classification Integrity  
Classification governs how metadata may be stored, exported, or exposed.  
Documents **inherit the classification** of their parent directory.

### **Classification Levels**
- **A — Air‑Gapped**  
  Highest security level.  
  Items marked **A** must remain isolated from networked systems.  
  **No public‑facing registry exports may include operational metadata**, including identifiers, relationships, or version history.

- **B — Confidential**  
  Sensitive internal material.  
  Public‑facing registry exports must **redact operational metadata**, including:  
  - directory identifiers  
  - version numbers  
  - document type codes  
  - classification letters  
  - cross‑references  
  Only the existence of the item may be disclosed.

- **C — Controlled**  
  Internal but non‑sensitive.  
  Registry exports may include identifiers and type codes, but must not include internal operational notes or dependency graphs.

- **D — Draft / Public‑Safe**  
  Lowest sensitivity.  
  Full registry metadata may be exported, including identifiers, type codes, version numbers, and relationships.

### **Registry Export Rule**
When generating public‑facing registry exports:

- **A‑classified items** → *fully omitted*  
- **B‑classified items** → *included only as redacted stubs*  
- **C‑classified items** → *included with limited metadata*  
- **D‑classified items** → *fully included*

This ensures sensitive operational metadata is never exposed outside its intended security boundary.

## 🧱 Document Type Codes  
Document type codes are short, fixed identifiers describing the **function** of a document.

- **spec** — Specification  
- **note** — Notes  
- **reg** — Registry  
- **prj** — Project  
- **ref** — Reference  
- **doc** — General document  
- **proc** — Process / SOP  
- **arch** — Architecture  
- **test** — Test / Validation  
- **plan** — Planning / Roadmap  

These codes are stable and non‑overlapping.

---

## 🔢 Version Numbering  
Version numbers are **3‑digit sequential integers**:

```
VVV = 001 → 002 → 003 → …
```

Version numbers represent **document revisions**, not semantic versioning.  
Semantic versioning (if needed) is stored **inside the document**, not in the filename.

---

## 🧩 Inheritance Rules  
1. **All documents inherit the directory’s identifier.**  
2. **Classification letter is shared between directory and documents.**  
3. **Directory year and document year must match.**  
4. **Document type codes must follow the approved list.**  
5. **Version numbers increment per document, not per directory.**  
6. **Security restrictions apply uniformly to all items within a directory.**

## 🧠 NLP, Database, and Graph Considerations  
### NLP Extraction  
The filename structure allows deterministic extraction of:
- year  
- directory ID  
- classification  
- document type  
- version  

### PostgreSQL Schema  
Recommended fields:
- directory_id  
- year  
- classification  
- doc_type  
- version  
- path  
- content  

### Memgraph Graph Model  
Nodes:
- Directory  
- Document  

Edges:
- `CONTAINS` (directory → document)  
- `VERSION_OF` (document → previous version)  
- `TYPE` (document → type node)  
- `CLASSIFIED_AS` (document → classification node)

## 📌 Compliance  
All new directories and documents **must** follow this specification.  
Registry files must track:
- next directory ID  
- next version number per document type  
- classification changes  
- export restrictions based on classification integrity rules
